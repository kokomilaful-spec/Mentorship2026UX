訪談心法

問「上一次」，不問「你會不會」

別問未來（陷入預測偏誤）

「如果我們未來推出『AI 自動排程』功能，你會想用嗎？」

人類極度不擅長預測自己的未來。這種問法只會誘發「討好型回應」，你拿到的是零成本的善意，而不是真實的付費意願。

改問過去（還原物理情境）

「回想一下你這週最後一次手動調整行事曆是什麼時候？那時候你碰到了什麼狀況？當時你怎麼解決的？」

痛點一：記憶模糊
Event Reconstruction 事件重建法
核心困境：受訪者說「我不太記得」——真實的情況常常是模糊的，特別是非日常的高摩擦行為。
破局技巧：不要硬逼他回憶，而是靠「錨點」幫助記憶。看他的週曆、手機相簿、信箱歷史、App 通知紀錄。
實戰例子：「這週二下班後，你在捷運上打開 App 時，第一個點擊的畫面是什麼？」與其問一個空蕩蕩的「上次你什麼時候…」，不如用「時間 + 地點 + 情境」三層錨點，讓記憶水落石出。
痛點二：防範吹牛
Show, Don't Tell 當場操作法
核心困境：「你會這樣用嗎？」時常換來理想自我的回答。受訪者未必有意欺騙，只是條件反射地呈現社交得體的版本。
破局技巧：邀請他當場操作真實的產品或介面，別用假設。「方便的話，直接打開【購物車／歷史紀錄／訂單】，我們一邊看一邊聊？」
實戰威力：當場的操作證據能直接擊碎「理想自我」。他點擊了哪裡、停頓了多久、最後選了什麼——這些才是真實行為的記錄。
追問陷阱
避免一直問「為什麼？」
為什麼這是陷阱：「為什麼」是理由題，易觸發防衛心與合理化。受訪者會下意識地「編故事」——給一個聽起來光榮或聰慧的原因。
改問方式：「當下是什麼讓你選這個，而不是那個？」這問的是決策過程，而非事後理由。或者「你記得當時的感受嗎？」——情感比理由更誠實。
進階應用：連續追問 3 次「為什麼」之後，他開始編製；但如果改成「那時你想到過其他選項嗎？」「你有試過…嗎」，就回到了具體行為的對話。
Data × UX 連結
訪談發現 → 數據假說 → A/B 驗證
訪談挖出的卡點：在 5 場訪談中，3 個用戶都說「一邊抱小孩、一邊結帳時會卡住」。
轉成數據假說：結帳頁面停留時間 >3 分鐘且最終放棄的用戶，是否在特定時段（例如晚間 6-9 點）佔比更高？他們的裝置是否以行動版為主？
後續驗證：Data Team 跑 SQL 確認：「這 10 萬個放棄結帳事件中，符合『停留 >3min』的有多少％？其中有沒有明顯的『分身乏術』信號（如：快速點擊、頻繁返回）？」一旦規模化驗證，就能決定該功能是否值得做。

01 · 定義異常行為訊號

Data 起手式 ➔ 拋出「量化斷崖點」（如 Spotify 1 秒秒切率異常）

UX 交叉詰問 ➔ 追問「時空物理脈絡」——什麼裝置？什麼時段？藍牙連動狀態？

Data 負責畫出問題的邊界，UX 負責還原現場的物理維度。

數據指出「哪裡值得問」，訪談補上「為什麼」——兩邊帶著同一個假說出發，才會有交集的決策。

商業本質不同，北極星就不同——體驗設計必須跟著變現模式走，沒有一招打天下的公式。

最痛的量化指標
為什麼是 Skip Rate，而不是 DAU？
訂閱制的獲利邏輯，和廣告業完全不同。
01
DAU 是訂閱制的「虛榮指標」
廣告業（FB／YouTube）靠 DAU 變現；但 Spotify 用戶每月固定付 149 元——聽 1 首或 10,000 首，收到的錢都一樣。DAU 只是健康指標，不是驅動成長的北極星。
02
Skip Rate 是退訂的「領先指標」
訂閱制真正的死穴是退訂（Churn），但退訂是「滯後指標」——看到時已來不及。頻繁秒切（ms_played < 2000ms）是退訂的前兆，讓你能提前介入。
03
每一次秒切，都是核心價值破滅
Spotify 賣的是「懂你的懶人體驗」，不是播放器。每次秒切都是一次微小摩擦（Micro-friction）；累積起來，用戶的「體驗帳戶」就會破產 → 退訂。

Hypothesis-Driven Designer Canvas

實戰拆解：一張 Canvas 如何終結會議室的跨部門內耗

上一頁的假說卡，攤開就是團隊的共用工作桌——Need 承接異常，Test 定義成功，Learnings 記錄結果。

Need
Define a user need to test against
Data 異常

ms_played < 2000ms（秒切）在 appload 場景高頻發生。

UX 脈絡

早上連上車用藍牙的瞬間，被昨晚的音樂自動播放「突襲」。

Hypothesis
Design a solution to pass the test
IF WE:

取消藍牙連線自動播放，改為彈出「接續昨晚播放？」智慧按鈕。

THEN:

消除早晨通勤的認知摩擦。把控制權還給用戶，在防止體驗帳戶透支（降低 Skip Rate）的同時，保留「無縫接續」的產品美意。

Test
Decide how to test and what success looks like
WE'LL PROCEED IF:

appload 觸發的秒切率
↓35%
且該功能的整體滿意度維持 4.5 星以上。

Learnings
Run the test and capture feedback
護欄警報

滿意度跌至 3.2 星（視覺負荷過高）。

Next Step（Pivot）

假說推翻。取消畫面按鈕，改為純「語音提示」，徹底解放駕駛雙眼。

✨ 優秀的亮點（Why it works）
1. Need：數據與情境雙軌
同時提出數據異常 (ms_played < 2000ms) 與用戶痛點（早上上車被突襲），讓團隊有高度共識。
2. Hypothesis：IF-THEN 清晰具體
IF 明確說方案（彈出智慧按鈕），THEN 連結核心價值（消除認知摩擦、還控制權）。
3. Test：主指標+防護網
秒切率下降 35%，同時維持滿意度 4.5 星以上，雙重驗證確保不傷害既有體驗。
4. Learnings：快速轉軸（Pivot）
護欄指標成功發揮作用，在引發大規模客怨前攔截錯誤——這就是 HDD 最大的價值。

質化研究 · 深度實踐

質化的核心：發現未知，建立假說

UX 與商業，各有一套「問為什麼」的方法。

UX 質化
探索心智模型與價值摩擦
脈絡訪查——走入真實場景，抓實驗室測不到的認知過載
日誌研究——追蹤 1-2 週的長週期互動，抓情緒轉折

關鍵不只是「好不好用」，是價值摩擦——使用者根本不認同這功能的核心價值嗎？

Business 質化
解構市場動態與可行性
客戶顧問委員會 CAB——頭部客戶閉門會議，看 2-3 年策略方向
Win/Loss 分析——深訪簽約成功／流失客戶，抓真實價格敏感度

往往揭示非技術性的成交阻礙：合規風險、採購流程、內部政治。

Data × UX 怎麼一起工作

不是「定量 vs 定性」，是一個閉環

規模化效率（Scale）× 深層同理心（Empathy）——雙向融合，輪流接棒。

① 發現異常
Data Team 觀察到後台指標異常
右下象限：A/B 測試、產品埋點／行為 Log
「某個環節的流失／異常率，比其他環節高出一大截。」
→
② 挖掘根因
UX 透過訪談與觀察追問
左上／左下象限：使用者訪談、易用性測試
「原來使用者誤解了這裡的設計語意。」
◄
③ 大規模驗證，回到 ①
Data 把質化長出的假設，用數據在全體用戶上驗證（驗證 HDD 卡的 Will result in／When we see）
「問題真的解決了嗎？範圍比想像中更大，還是只是個案？」——驗證完畢，回到①繼續盯下一個異常。

分工不是搶地盤：Data 做 pattern 識別，UX 做意義賦予。AI 起草，UX 當編輯——防止它誇大痛點、混淆無關回饋。

經典案例對比

把「假設」變成「事實」

在實務上，不論是 B2C 還是 B2B 產品，當我們屈服於 Stakeholders 的壓力而問出「假設性問題」時，往往會得到虛無的「安全感」，進而導致災難性的開發決策。

關鍵在於：用 UX 問出「過去的真實行為（Why）」，並用 Data 驗證「後台的規模化指標（What）」。

敏捷快篩 · UX × Data 聯手

日常迭代中的『體驗快篩』三板斧

🎙️
15 分鐘雷射訪談
UX 輕量行動：只聚焦最近一次觸發「特定行為」的極端用戶，進行現場還原。

Data 聯手點：用 SQL 撈出「剛完成高價值轉換」或「剛遭遇結帳失敗」的用戶名單，精準篩選。

👁️
錄影與軌跡側寫
UX 輕量行動：直接挑 10 支代表性的 Session Replay，看用戶如何掙扎。不一定要約真人。

Data 聯手點：將「滑鼠狂點」的質性觀察對齊後台「Rage Click 憤怒點擊」埋點，把個人觀察規模化。

🧪
RITE 快速迭代測試
UX 輕量行動：只測 3 人，發現痛點當天改原型，隔天再測 3 人。用最低成本排雷。

Data 聯手點：用易用性測試排掉架構性風險，上線後的 A/B Test 才能「優中擇優」，而非「垃圾互比」。

資深心法：在日常快速迭代中，放棄厚重的研究規畫。日記研究或焦點小組留給長線戰略；這三把輕量工具，才是你每天用來對齊『數據假說』與『體驗盲區』的貼身小刀。UX × Data，在這三種場景裡聯手。

案例一 · 訂閱與體驗驅動型

Spotify：把矩陣套進真實產品

商業模式建立在長期訂閱（LTV）上，流失是致命傷——核心是建立習慣與對推薦算法的信任。

UX × 質化
情境與情緒脈絡
日誌研究——追蹤通勤／運動／專注／派對等場景下的聽歌習慣
心智模型訪談——用戶怎麼定義「好音樂」？對 AI DJ 的驚喜／反感臨界點在哪？
UX × 量化
流暢度與黏著度指標
Skip Rate——30 秒前跳過的比例（高＝算法體驗差）
Time to First Play／DAU/MAU——黏著度
Business × 質化
付費壁壘與續訂意願
定價策略訪談——漲價時不同用戶群（個人／家庭／學生）的心理帳戶與替代方案
非主動流失訪談——信用卡過期、跨國旅行等原因，理解重啟訂閱的阻力
Business × 量化
健康度與單位經濟
Premium Conversion Rate／Churn Rate
ARPU——搭售（Podcast、Soundbooks）對客單價的拉動
核心橋梁

推薦演算法的「信任與留存迴圈」

UX 的優劣直接決定算法表現，進而影響商業留存。

UX 質化

發現用戶在特定時間有特定情緒（週一早晨需要振奮、深夜需要療癒）

UX 設計

針對情緒分類做優化，例如推出個性化的 Daylist 歌單

UX 量化

該歌單 30 秒 Skip Rate 下降，Session Duration 提升

商業回報

用戶對推薦產生依賴，產品「黏性」提高 → 續訂率提高（Churn Rate 下降）

在 Spotify，研究員像在經營一家高級俱樂部——用質化理解生活風格、用量化優化個人化氛圍，讓會員捨不得離開。

核心橋梁

從「降低認知負荷」到「提升客單價」

電商的 UX 改善能立竿見影反映在財報上。

痛點

質化發現：結帳時看到「還差 150 元才免運」，退出找商品湊免運，但太難找，最後放棄購買。

數據驗證

量化交叉比對：購物車流失率在客單價 800-1000 元（免運門檻 1000 元）時達到高峰。

設計方案

購物車頁直接提供「智能加購推薦組合」，一鍵湊免運。

商業回報

結帳流失率下降，AOV 與整體 CR 同時提升。

在電商，研究員像在優化一條高速公路——掃平路障、給清晰指示牌，讓用戶最快抵達結帳終點。

財務漏斗與單位經濟
LTV／CAC——健康標準通常需大於 3
流失率／NRR——反映長期市場黏著度
漏斗轉換／Cohort 分析——評估不同管道的長期價值

質化找方向，量化定規模——兩者缺一，決策都站不住。

核心橋梁

用商業聽得懂的語言，講 UX 的價值

Goals → Signals → Metrics：把質化發現，翻譯成商業回報。實例：優化 Onboarding。

UX 質化發現

Dashboard 資訊過載，新用戶找不到「第一步」

UX 量化信號

完成率僅 35%；首頁停留長但無點擊

商業量化影響

首週流失 60%，CAC 居高不下

設計行動

簡化流程，導入引導式進度條

商業回報

完成率→70%／留存+15%

這樣，把「設計決策」跟「財務指標」綁在一起。

最具說服力的成本論證

減少「失效需求」Failure Demand

省下的客服成本 ＝ 減少的客服進件量 × 單通客服平均處理成本

設計不良讓使用者因操作出錯、理解障礙而聯繫客服——這筆帳，比「提升滿意度」更能說服高階決策者。

向老闆說話

說服老闆的終極武器：質化 × 量化並進

只講量化
老闆聽到

「流失率高」「Skip Rate 升高」「轉換率下降」

老闆追問

「我知道發生什麼，但你要怎麼改？」

只講質化
老闆聽到

「用戶說很挫折」「卡在付款流程」「擔心詐騙」

老闆追問

「這是少數人特例嗎？影響有多大？」

質化 + 量化
老闆聽到

「65% 的購物車流失都卡在付款；為什麼？問卷＋訪談發現信任痛點。改版後流失率下降 15%」

老闆決策

批准投入做

核心洞察：三角測量（Triangulation）——從三個角度逼近真相。量化告訴你「規模」，質化告訴你「根因」，合起來才是可投資的決策。

單純量化的風險：看到了效果，卻不知道原因（可能改錯地方）。單純質化的風險：有故事，但影響範圍不明（可能只是個案）。質化＋量化則是：既有規模證據，又有具體解法。
